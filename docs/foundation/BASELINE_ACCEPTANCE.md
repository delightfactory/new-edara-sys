# سجل اعتماد نسخة الأساس الحالية

الحالة: **IN_PROGRESS**. هذا هو سجل الإغلاق الحالي بعد الانتقال إلى قاعدة التجربة الكاملة، ويُقرأ مع أدلة التأهيل السابقة؛ لا تلغي نتائج المرشح القديم حدود الاختبارات الجديدة. فرع العمل `codex/baseline-ui-polish`، والتجربة الحية على `http://127.0.0.1:5180`. الأصل في D محفوظ، والإنتاج لا يُعدّل.

## بوابات الإغلاق بالترتيب

1. **الخدمات والبيانات:** تجهيز القاعدة المستقلة وتحديثات الأساس تم؛ 26 فحص API وحدث Realtime فعلي موثقان في FULL_LOCAL_TEST_DATABASE.md. إعادة التأهيل التشغيلية على القاعدة الكاملة مفتوحة؛ بيانات أغسطس والمرفقات القديمة غير المتاحة حدود معلنة.
2. **الوظائف:** المبيعات والتحصيل والمرتجعات والمشتريات والاستلام والمخزون والقيود والصلاحيات لها أدلة فعلية مصطنعة على C3 السابق. المطلوب تأكيد التوافق على البيئة الكاملة دون الكتابة على بيانات المستخدم المستعادة أو إفساد اختباراته. يلزم فحص إنشاء/حفظ/نتيجة/رفض/تصحيح ممثل، وليس مجرد ظهور الصفحات.
3. **الواجهة:** معالجة عيوب المستخدم المادية، ثم المسارات الأساسية على 390/900/1440، والهاتف القصير عند وجود overlays. ترتيب الدفعات: البيع والعملاء والمنتجات والمشتريات والمخزون، ثم المالية والعمل وHR، ثم التقارير والإعدادات. Claude يشارك في ملاحظات UX والتنفيذ؛ Codex يراجع ويختبر. حصر 129 مسارًا يظل حصرًا، ولا يتحول إلى PASS تلقائيًا.
4. **الأداء:** الاحتفاظ بتحسينات التحميل والجلسة والكاش السابقة؛ قياس تشغيل بارد ودافئ وانتقال ممثل على build محلي مع القاعدة الكاملة. لا مقارنة سرعة إنتاج من نتائج Vite dev، ولا استنتاج سرعة من حجم الحزمة فقط.
5. **المرشح النهائي:** تحديد SHA واحد، suite/type/lint/build محلية، تحقق خدمات/صلاحيات/Realtime/PWA واستعادة محدد، مراجعة Claude مستقلة، وتطابق commit المحلي مع GitHub. لا إعادة الفحوص الناجحة إلا بعد تعديل مؤثر أو دليل إخفاق جديد.
6. **الاعتماد والتسليم:** تقرير واضح بالنتائج والحدود والملاحظات المفتوحة وخطة رجوع. لا يوصى بالاعتماد مع مانع مؤثر في حفظ المعاملات أو الصلاحيات أو ظهور الوظائف الأساسية. موافقة النشر على الإنتاج مستقلة وتأتي بعد عرض المرشح المؤهل؛ AI وإعادة البيع بعد اعتماد الأساس.

## قواعد تمنع الدوران

- دفعة واحدة محددة، وكاتب واحد لكل ملف؛ لا مكتبة أو إعادة هيكلة أو تنظيف شامل بلا مانع مثبت.
- محاولة تصحيح ثانية فقط عند وجود تشخيص جديد، ثم تسجيل السبب والتحول إلى عمل مستقل؛ الوقت لا يحول الفشل إلى نجاح.
- الأخطاء التشغيلية تتقدم على التجملات. تحسين جميع صفحات DS2 ليس شرطًا يُضاف بلا نهاية إلى اعتماد الأساس؛ العيوب المادية في المسارات الأساسية تُغلق أولًا، وباقي التحسينات لها سجل منفصل.
- بيانات ومفاتيح التجربة والأدلة ذات بيانات العملاء تبقى خارج Git. لا معاملات اختبار على الإنتاج، ولا حذف للسجلات المستعادة.

## الدفعة الجارية

Claude نقل التحويل الذكي من زر عائم يغطي بيانات بطاقة المبيعات إلى إجراء ثانوي مسمى في الترويسة؛ الصلاحية ومعالج الفتح والحوار محفوظة. فحص الهاتف أثبت إجراءً واحدًا بارتفاع 44px دون تمدد أفقي، وفتح الحوار وإغلاقه بـEscape دون تنفيذ تحويل.

فحص أولي حي على الهاتف لقوائم العملاء والمنتجات والمشتريات والمخزون: ظهرت عناوينها ومدخلاتها، ولا تمدد أفقي أو alert panel. هذا **ROUTE_SMOKE** فقط، وليس قبولًا للحفظ أو لكل حالات الخطأ. بقية الأجهزة والمهام تُسجل بعد التحقق الفعلي.

## نتائج التحقق الحالية — 11 أكتوبر 2026

- **LOCAL_SUITE_PASS:** 142 ملفًا / 1079 اختبارًا. lint وTypeScript وبناء Vite/PWA نجحت. البناء خارج الشجرة وعلى API محلي 60431، مع تعطيل تحميل env الإنتاج. بقي 5180 حيًا؛ خادم البناء المعزول على 5181 للتأهيل فقط.
- **ROUTE_SMOKE:** 24 حالة = العملاء والمنتجات وفواتير الشراء وأرصدة المخزون وإيصالات الدفع والعمل والموظفون والأدوار × 390/900/1440. عنوان واحد، لا تمدد أفقي ولا alert panel مرصود. لا يُفهم ذلك كاعتماد جميع السجلات أو الإجراءات أو الحالات.
- **PWA_SHELL_PASS:** دخول فعلي على البناء، ثم reload يخدمه Service Worker، ثم reload دون اتصال مع بقاء واجهة المستخدم والدخول، وإعادة الشبكة بنجاح. ملفات API لم تظهر مخدومة من SW في العينة. التغييرات الشبكية المؤقتة أُعيدت في تبويب التأهيل؛ تبويب المستخدم لم يُعدّل.
- عينتا شبكة منفصلتان: bypass SW وتعطيل cache ثم reload، وبعد إعادة الإعدادات reload دافئ. كل عينة 40 طلبًا بلا HTTP 4xx/5xx، ونافذة الشبكة المرصودة 529ms في كل منهما؛ العينة الدافئة تضمنت 11 استجابة من SW. هذه نافذة شبكة محلية بعينتين محدودتين، ليست زمن التفاعل أو قياس أول دخول أو تحسنًا مقارنًا بالإنتاج.
- **AUTHENTICATED_SQL_RPC_PASS:** عقد تعديل مسودة مرتجع المشتريات على القاعدة الكاملة بدور authenticated وحساب الاختبار الفعلي: حفظ البنود مع تعديل الرأسية، تصفير الإجمالي عند إفراغ البنود، تقريب المجاميع إلى 0.69. المعاملة كلها ROLLBACK، وفحص لاحق أكد غياب المنتجات والمورد والمخزن والمرتجع المصطنعة. لا تعديل لترحيل أو بيانات تشغيل مستعادة؛ لا ادعاء حفظ HTTP أو تأهيل جميع المحاسبة من هذا الفحص.
