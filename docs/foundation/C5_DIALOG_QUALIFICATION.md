# دورة حياة النوافذ وحقول التاريخ — C5

## المشكلة المثبتة

عند الأب `f3f67999c423b431ab7b0bcfa4864206ca137cb0` أثبت Chromium الفعلي أن Modal التقليدية لا تنقل التركيز داخلها أو تعيده لزر الفتح، وأن Tab يخرج من النافذتين. ResponsiveModal تستخدم id ثابتًا للعنوان، وConfirmDialog بلا اسم مرتبط بعنوانها. إغلاق التابعة بـEscape ترك الأم مفتوحة لكن عمق النوافذ صفر والتمرير غير مقفول. الملاحظة الفعلية لا تقول إن النافذتين أُغلقتا معًا. التاريخ الداكن كان color-scheme=normal. الأدلة قبل التغيير في `C5_DIALOG_DISCOVERY_EVIDENCE.json`؛ البيئة تركيب اختبار محلي بلا أعمال أو خلفية.

مراجعة Claude المباشرة `f8881cfc-fba7-4e1f-866d-f9d0bbce67c8` أعطت GO بعد فحص المصدر. أصل العدّ: cleanup يقوم بـpop عند الإغلاق ثم effect الفرع المغلق يقوم بـpop مرة أخرى. أصل قفل التمرير: كل نسخة تعيد overflow إلى فارغ دون اعتبار نافذة أخرى. بقيت سياسة إغلاق البيانات غير المحفوظة وقرار السماح بالإغلاق مسؤولية caller.

## التغيير المحدود

`useDialogLifecycle` يخدم المكوّنين الموجودين؛ لا dependency أو portal أو native-dialog migration أو مدير عام جديد. قائمة خاصة للنوافذ المفتوحة تضبط التركيز وEscape وقفل التمرير؛ ليست حالة جلسة أو صلاحيات. الإجراءات تستخدم عدّاد FAB الموجود بدخول/خروج متوازن، وتستعيد overflow الأصلي بعد آخر إغلاق. لا listener أو تغيير قفل من النسخ المغلقة.

المفتوحة الأخيرة فقط تستقبل Escape، مع احترام defaultPrevented، وTab يعيد حساب عناصرها المرئية غير المعطلة كل مرة. التركيز البرمجي خارجها يعاد إليها؛ التركيز يرجع لزر الفتح إن بقي متصلًا، أو للنافذة الباقية. الـref يحفظ callback الحالية دون إعادة ربط الدورة مع كل callback inline. FocusCapture يحفظ relatedTarget قبل تأثير layout عند وجود React autoFocus، ولا يستبدل autofocus الذي وضعه caller داخل النافذة.

أضيف useId لعناوين النافذتين واسم ConfirmDialog عبر h3 الموجودة، وخيارا ariaLabelledBy/ariaLabel للcaller بلا عنوان. زر إغلاق Modal التقليدية صار type=button لمنع submit ضمني عند استضافته داخل form؛ callback الإغلاق نفسها محفوظة. DOM div/CSS والتخطيط المتجاوب وأزرار/رسالة/variants/loading في ConfirmDialog بقيت كما كانت. لم نغيّر سياسة Escape أثناء loading: هو ما زال يستدعي onCancel؛ قرار منع الإلغاء أثناء عملية محفوظة يعود لcaller.

CSS من أربع سطور يضبط color-scheme للـ`.form-input[type="date"]` بحسب ثيم التطبيق؛ لا تغيير قيم/دقة/حدود التاريخ أو بقية أنواع الحقول. ملاحظة أيقونة التاريخ في دفعة REPORT053 السابقة مؤهّلة الآن ضمن هذا الحد فقط، وليست قبولًا لكل dark UI.

## ما يبقى مفتوحًا

المراجعة النهائية المباشرة من Claude في الجلسة نفسها انتهت بـPASS، exitCode=0 وreadOnlyViolation=false، بعد فحص hook والمكونات والاختبارات وأدلة التأهيل. لم تُجرَ تعديلات production بعد هذه المراجعة. وصفه المختصر لقواعد التاريخ لا يُستعمل كدليل إضافي: المصدر يضبط ثيم التطبيق فقط، بينما اختلاف ثيم النظام اختُبر في المتصفح. الاعتماد هنا على المصدر والنتائج المسجلة، وبحدود هذه الدفعة.

هذه بوابة المكونات الثلاثة الأساسية؛ overlays أخرى مثل AsyncCombobox داخل مسارات الأعمال، App/shell والعمليات المالية/المخزنية المحفوظة وعكسها، Realtime، واستعادة البيئة والقياس/مراجعة SHA النهائي باقية للتأهيل. برنامج DS2 العام لا يكتمل بهذا الإصلاح. لا تغيّر على ملفات REPORT053 الثلاثة أو حالات مالكي DS2، ولا main/DS2 merge أو نشر أو بيانات إنتاج.
